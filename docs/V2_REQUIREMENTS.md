## A. 正式扫描前必须改的

### A1. 旋转中心改为"抓取中心"

现状：工具原点是 right_gripper_base_link，偏移公式为 T0 @ Trans(δ) @ Rot(θ)，旋转绕夹爪基座。倾斜时传感器中心会被甩出去很远；视觉扫描的瓶子坐标系 B = T0，"绕瓶轴公转"实际绕的是瓶子后方的一个点。

修改：
1. 配置新增 tool.grasp_center_in_tcp（TODO）：从夹爪基座到"两指传感面中心连线中点"的固定变换 G。来源可以是 URDF/CAD，也可以是实测，并在配置里注明依据。
2. 接触扫描目标位姿改为 T_target = T0 · G · Trans(δ) · Rot(θ) · G⁻¹。
   - 平移的数值结果应与旧公式完全一致。用单元测试证明这一点，并证明三点验证的三个目标位姿不变。
   - 再加一个单元测试：任意倾斜下，抓取中心在基座坐标系中的位置不变。
3. 视觉扫描：
   - 瓶子坐标系改为 B = T0 · G，公转绕经过 B 原点的瓶轴进行（侧抓时瓶轴沿 l，顶抓时沿 a）。
   - 新标签为 inv(T_measured · G) · B。旧标签 inv(T_measured) @ T0 也保留，便于追溯。
4. dry-run 输出中列出每个目标的抓取中心位置，以及它相对 T0 抓取中心的偏移。
5. "名义接触部位"（瓶身/瓶颈/瓶盖/空）改用抓取中心的高度计算，计算方式写进文档。

### A2. 力控制来源【核对】

先汇报以下情况：
- PROBE 和 SQUEEZE 当前用的是什么：你新写的软件力环，还是我现有的力控制器？
- 现有控制器的接口：力的定义（每指、均值还是总和）、单位、如何启动和设定目标、如何退出，以及退出后夹爪处于什么状态。
- 如果没有直接复用现有控制器，具体原因是什么。

然后按以下方式修改：
1. 配置新增 force.controller，可选 existing 或 bridge_loop。首选 existing：调用现有控制器但不修改它的代码，把启动、设定目标、退出、退出后确认这一整套交接做完整。
2. 如果 existing 无法安全接入，保留 bridge_loop，但新增入口 validate-force，要求如下：
   - 在 T0 用指定的控制器重复"闭合→夹紧→保持→松开"N 次（默认 10 次）；
   - 记录：接触过冲（接触后的力峰值）、进入目标力带所需时间、稳态均值与波动、最大力；
   - 两种控制器都能分别运行，并输出对比表。
   - 正式扫描（非三点验证）启动前，要求存在一份经我确认的力控验证报告，配置里登记报告路径。
3. 配置新增 force.target_definition，可选 per_finger、mean、sum，必须与部署系统一致。每个时刻的每指法向力、均值、总和全部记录。
4. 配置新增 force.unit，可选 sdk 或 N。
   - 选 sdk 时不阻塞运行，但所有图表和 CSV 都要标明单位是 SDK 单位。
   - 选 N 时必须提供换算系数及其依据。

### A3. 左腕相机与非实验臂【核对】

先汇报：左腕相机是否装在左臂（非实验臂）上；当前 session 是否记录了左臂位姿。

如果确实装在左臂上，按以下修改：
1. prepare 新增"左臂停放位姿"步骤：
   - 提示我用 move-tcp --arm left 选一个能同时看清瓶子和右夹爪的位姿；
   - 记录左臂 TCP 位姿和关节角到 session_meta。
   - 实验程序本身绝不发送任何左臂运动命令。
2. 每次运行开始和每次 CHECK 时，只读核对左臂位姿。平移变化超过配置阈值（默认 1 mm）或旋转超过 0.5° 时，停止并提示。
3. 视觉扫描的元数据要写清楚两路相机的性质：
   - right_wrist 是眼在手上，A1 的标签直接适用；
   - left_wrist 是固定外部视角。
   每张图都要保存 T_base_rightTCP、B（基座坐标）和左臂位姿，这样两路相机都能与瓶子关联起来。
4. 文档里明确：左腕相机兼作第三视角，用于事后回看倾倒、推瓶、滑动。

### A4. 软件停止测试

新增入口 stop-test。它只在自由空间运行，从 axis_test_pose 出发，需要 --real 和 MOVE 确认，由我手动启动，所有路径都要经过安全检查。

1. 测试一：以配置中的实验速度，沿一个安全方向移动 50 mm。程序在中途指定时刻触发软件停止（与 Ctrl-C 走同一条代码路径），记录：
   - 停止请求时刻；
   - 实测停稳时刻；
   - 停止请求之后的额外位移。
2. 测试二：在子进程中执行同样的移动，中途用 SIGKILL 杀掉子进程。主进程只读监视实测位姿，记录机器人最终停在哪里，以及它相对最后一个已发布目标的位置。
3. 两个测试各重复 3 次，输出报告。
4. 正式 contact 和 visual 实机运行前，要求存在一份经我确认的停止测试报告，且额外位移不超过配置阈值。

### A5. 启动行为

1. 运行开始时先计算待做项。没有待做项就直接退出，不发任何运动命令。
2. 每次运行的第一段运动（当前位姿 → T_check），无论是否单步模式，都先显示起点、终点和路径检查结果，要求输入 MOVE 确认后才执行。
3. 视觉扫描结束后回到 T_check（经路径检查）。检查不通过就停在原地，并提示我处理。

### A6. 扣零前检查

软件扣零前必须同时满足以下条件，否则拒绝扣零并说明原因：
- 夹爪开度在 w_open ± 容差内；
- 如果 session 空载参考已存在：DD 相对参考没有接触印迹；
- 100 帧内法向力的波动低于阈值；
- 如果是 session 内的第一次连接、还没有空载参考：除开度检查外，还要我输入确认。

每次运行的零点值写入 meta。与上一次零点相差超过阈值时给出警告。

### A7. LOWER 改为检测卸载

1. 下降过程中监测两指沿竖直方向的切向力之和（坐标映射未确认时，改用切向力合力的幅值）。
2. 满足以下任一条件就停止下降：
   - 该值降到 HOLD 均值的配置比例以下（默认 20%）；
   - 到达提起前的原高度。
3. 任何情况下都不得低于原高度。
4. 记录检测到卸载时的高度，以及它与原高度的差值。

### A8. 命令话题发布者检查

doctor 和所有 --real 入口启动时，列出两条臂和两个夹爪命令话题的全部发布者。除本程序外还有其他发布者时，拒绝启动并打印这些发布者。

## B. 数据质量与效率

### B1. 轻触与保持的取值方式

1. PROBE 的结束条件改为：力连续保持在 F_probe ± 容差内达到 probe.settle_s（默认 0.2 s）。
   - 设超时 probe.timeout_s；超时后标记 probe_not_settled，流程照常继续，但该次描述子带上这个标记。
2. 描述子取值：
   - PROBE：稳定窗口内最后 probe.window_frames 个有效 DD 帧（默认 5 帧）的中位数；
   - HOLD：中段 hold.window_s 窗口（默认 0.5 s）的中位数；
   - 同时保存所用帧的索引、这些帧对应的实际力，以及窗口内的 DD 帧缺口统计。
3. 新增指标"轻触印迹信噪比"：PROBE 窗口内的 DD 接触总量 ÷ 空载噪声，写入 meta 和汇总表。

### B2. 闭合速度与停滞检测

1. dry-run 计算并打印"接触过冲行程估计"，即闭合速度 × 检测延迟。检测延迟按实测的 DD/力帧率取 2 帧，可配置。估计值超过 close.max_overtravel_mm 时报错。
2. 每次试验都记录实际的接触过冲（接触后的力峰值）。
3. 停滞检测的可靠性检查：闭合速度 × 停滞窗口必须至少是开度读数分辨率的 5 倍，否则 dry-run 报错。

### B3. 分析支持多个 session

1. analyze 改为可接收多个 SESSION 位置参数，配合 --output 使用。
2. 偏移统一用"相对各自 T0 抓取中心"的量，session 作为一列分组变量。
3. 拟合和热图同时输出合并结果与分 session 结果。
4. 如果不同 session 的关键配置不一致（G、DD 处理方式、力的单位和定义、工具定义），给出警告。

### B4. 新 session 的门槛

1. 对硬件和桥接相关配置计算一个哈希。若已有通过三点验证的 session，且哈希相同，新 session 只需 prepare 加一次零偏移单步试验（--commissioning-lite）。
2. 纯视觉 session 用 visual --commissioning：前 8 个点单步执行，不要求接触三点验证。前提同样是桥接哈希已在某个 session 中验证过。
3. 硬件或桥接配置一旦改变，恢复为完整的三点验证。
4. 主机重启后新建 session，同样适用 lite 门槛。

### B5. T0 微调默认开启

1. --tune 改为默认开启，提供 --no-tune 跳过。
2. 记录微调结束时两指质心的残差（像素；有像素间距时同时给出 mm）。
3. 记录 T0 时抓取中心离桌面的高度：一个由 T0·G 和桌面 z 计算得到，另设一个输入框让我填卡尺实测值作交叉核对。两者相差超过阈值时警告。

### B6. 缺标定时的输出方式

1. DD 像素间距未知时，描述子用像素输出（列名带 _px），斜率以 px/mm 报告；像素间距已知时，同时输出 mm。
2. 力相关的列都带上单位标签。
3. 只有确实无法计算的量（例如力矩单位未确认时的 CoP）才输出 NaN。

### B7. 开度重复性测试

新增入口 opening-repeat，需要 --real，首次运行必须单步：
1. 在 T0 用与 CLOSE+PROBE 相同的流程闭合到接触，然后松开，重复 N 次（默认 10 次）；
2. 输出接触时归一化开度的分布，以及开度读数的分辨率；
3. 可选：录入卡尺实测的"归一化值—mm"对照数据，拟合出开度映射。

### B8. 瓶位检查的提示

1. 框选提示改为：框选范围包含瓶身左右两侧的轮廓边缘，不要只框标签纹理。
2. 2 mm 标定提示改为：沿接近方向 a 移动瓶子。分别显示两路相机测到的位移，并报告各自的灵敏度。

### B9. 汇总表新增字段

在 summary.csv 中新增：
- 每次 CHECK 测到的两路像素位移（即闭合导致的瓶子位移）；
- APPROACH 结束、停稳后的到位误差，平移和旋转分开；
- 机械臂插值循环和力控循环的周期统计（均值、p95、最大值）；
- DD 和力数据的帧缺口统计；
- 接触过冲；
- 轻触印迹信噪比；
- probe_not_settled 标记；
- LOWER 时的卸载高度差。

### B10. 胶面原图与 DD 来源记录

1. 配置新增 record.gel_raw，可选 off、windows、full，默认 windows：只在 PROBE 和 HOLD 窗口内保存 39010 胶面原图。
2. session_meta 记录 DD 的处理来源：服务名称与版本、分辨率、dtype、量化方式。以后要和 UMI 示教数据对比时需要这些信息。

### B11. 写盘与控制循环解耦【核对】

先汇报：图像编码、H5 写入和控制循环是否在同一线程或进程中。
- 如果在同一处，重构为独立的写盘线程或进程，带有界队列；队列满时报警，不得阻塞控制循环。
- 用模拟模式下的压力测试，证明写盘负载不会拉长控制循环周期。

## C. 文档

1. README 只描述当前的公开 ROS 路线。旧的严格接口模板内容移到 docs/LEGACY.md，删除"真实模式保持禁用""尚不具备执行条件"等与当前路线矛盾的表述。
2. 两类确认项分开命名：
   - 配置中的 axis_mapping_declared、sensor_mapping_declared、camera_mounts_declared，表示"我已用 move-tcp 或手动按压确定了映射关系"；
   - session 中的 axis_verified 等，表示 prepare 现场复核的结果。
3. 操作指南补充以下新步骤：G 的确定、左臂停放位姿、stop-test、validate-force、opening-repeat，以及它们在整体流程中的位置。
4. 三点验证的通过方式改为：程序自动生成一页验收摘要，我输入 PASS 后才写入 commissioning_passed。摘要包含：
   - 最大力与 F_max；
   - 接触过冲；
   - PROBE 是否稳定；
   - 轻触印迹信噪比；
   - 零偏移试验的两指质心；
   - 越过瓶盖点是否走了无接触分支；
   - 到位误差；
   - 控制循环周期统计；
   - CHECK 结果。
