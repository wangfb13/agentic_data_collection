# a 轴三部分 skill 的完整闭环

本入口在同一版本中更新调用条件、恢复动作模型和退出条件，复用已有轻触、开爪退让、沿 a 平移、重新接触、夹紧及提起流程。`init/status/advance` 都是离线操作；只有 `run --real` 可以进入已有采集执行器。此轮开发没有启动真机。

## 版本和实验顺序

`A 规则采集 → 三部分联合训练 → 冻结版本 → development B → 诊断与 Agent 补 A → 重训`。

development B 达标后，执行事先冻结的独立 B。独立 B 通过才进入 `complete`；失败进入 `independent_failed`，不把独立验证数据拿去调模型。预算用尽是 `budget_exhausted`，不是达标。各轮模型、配置、标签来源、原始 TCP 训练流摘要、B 报告都保存并校验；不能覆盖旧模型或静默混入不同 T0、夹爪下限、硬件配置、目标定义的实验。

`planner.mode: llm` 复用已有 AgentProvider，真正调用语言模型提出 a 偏移、重复次数、理由、证据引用和预期结果。实际调用需要 `--allow-agent`，账户/代理沿用原 Agent 配置。模型不能改力目标、l 轴、动作边界、标签、达标标准，不能直接发机器人命令。没有授权或服务失败时保存状态并停在安全批次边界，不冒充已获得 Agent 意见。显式选择 `agent_evidence` 才使用确定性的规则补采，并在报告标注其不是 LLM。

## 三部分分别学什么

- 调用条件：双指接触质心 → 已在目标 / 需要恢复；有独立训练、阈值校准、留出验证，支持范围外或置信不足可拒绝。
- 恢复模型：复用原 20 维触觉描述子模型。A 的动作监督仍是实测 TCP 相对共同 T0 的反向 a 位移，属于“回到参考位置”监督，不是已证明的最佳动作。符合新标签协议且有执行回执的新 development B 成功轨迹可补充动作学习。
- 退出条件：双指接触质心 → 当前窗口达到 / 未达到目标。必须再通过已有新鲜观测、双侧内部接触、稳定时长和连续窗口检查，才能成功交回控制权。

两项状态模型使用 4 个质心坐标及其平方项的小模型；动作模型保留现有描述子和不确定度限制。三部分同轮重新训练、同一 model_id 发布；任一部分证据不足，整个版本不能进入 B。紧急退出/失败退出与“恢复成功”分别记录。不是把旧的固定 2 mm 判据改个名字，也没有通过放宽不确定度阈值强行启动模型。

## 先准备的定义与数据

1. 确认当前白瓶参考 T0 下双指的**目标接触区域**，保存可回看的两指触觉图/记录及人工判定说明。现模板是文字定义，现场必须明确具体合格区域；“碰到胶面”本身不够。零偏移如果不合格，应先重设参考，不要教模型回到错误位置。
2. 核对底盘/瓶子标记、传感器、轻触目标、白瓶闭合下限。示例参考是旧 A 的 0.336，仅为复用记录，不代表重新确认其能夹紧。0.334 和 0.336 的数据不能直接混训。若更换协议，先用现有流程采一个新参考会话，再在新 campaign 配置指定它。
3. 首批建议覆盖 a = -5、-2.5、0、+2.5、+5 mm，两只轻重白瓶平衡重复。示例每档总计 8 次（每瓶 4 次），共 40 次扫描，加原来的 4 次零点监测，共 44 次。偏移值只是实验设计，不自动决定标签。若这些偏移仍都属于目标区域，要重新界定可观察问题；不要硬标成失败或擅自扩大运动范围。
4. 每次标首次接触：需要恢复 / 已正常 / 不适用或无法判断；另标最终是否达标；再对每个实际记录的唯一接触窗口标是 / 否 / 不确定。窗口时间戳和目标定义 ID 随标签保存。标签中断后续跑只补标签，不重做已结束的物理试验。
5. 要有真实“需调整”和“未达目标”样本，也要有正常/达标样本。每个状态头每个类别至少需训练 4、校准 2、验证 2 个不同试验；按瓶子和重复块整组划分，窗口多不等于独立试验多。这只是最低训练门槛，不保证模型可用。
6. B 还必须出现真实修正：前状态、非零指令、实测位移与回执、动作后的新触觉、最终目标标签。失败/未恢复窗口同样保留。仅正常接触、零次修正的 B 不能验证恢复模型有效。

旧白瓶 A 的 26 条主要仍有几何监督价值，但当时的“已正常”未使用本次目标定义，不能静默当作新条件标签。只要录像/触觉记录足以独立判断，可以在**另存的审核数据副本**中按新协议重标；看不清的必须补采，禁止按计划偏移补造标签。

## 命令

仓库：`/home/dm/DM_das/bottle_grasp_experiment`。先复制并审核 `config.white_bottle_a_loop.yaml`。新配置与仓库配置放在同一目录，或使用绝对路径。示例 `physical_setup_confirmed: false`，故意保留离线状态；完成上述现场核对后，在**初始化前的新配置**中设为 true。冻结后的配置不允许修改。

先离线建计划，不连接设备：

```bash
cd /home/dm/DM_das/bottle_grasp_experiment
bash run_on_5090.sh skill-loop init \
  --config config.white_bottle_a_loop.yaml \
  --out outputs/white_a_joint_loop_run1
bash run_on_5090.sh skill-loop status --out outputs/white_a_joint_loop_run1
```

若仅想检查旧 A 能否启动新版，可选择新输出目录并加：

```bash
bash run_on_5090.sh skill-loop init \
  --config config.white_bottle_a_loop.yaml \
  --seed-session outputs/white_a_current_x5_20261109 \
  --out outputs/white_a_joint_loop_old_data_check
bash run_on_5090.sh skill-loop advance --out outputs/white_a_joint_loop_old_data_check
```

这会离线训练并列出缺口；默认不调用 LLM，也不会动机器人。旧标签不足时模型会被阻断，进入 `awaiting_agent`。不要通过修改 JSON 的 ready 字段绕过。

只有在完成现场服务、空载扣零、参考位姿与瓶子检查，并用现场确认过的配置初始化新 campaign 后，才使用以下真机入口（本次开发未执行）：

```bash
bash run_on_5090.sh skill-loop run \
  --out outputs/white_a_joint_loop_run1 --real --allow-agent
```

默认保留逐阶段确认，以及放瓶、换瓶和标签交互；并不是无人值守机器人。正常完成一批后自动训练、评估、让 Agent 提补采计划；下一批继续复用原有运动确认。运行中断后使用同一目录和命令恢复；标签补齐的那次调用只做补标，再次运行才继续采集。`--auto-stages` 可省略逐阶段确认，但不省略初始运动授权、换瓶与标签。

预算是新增**试验尝试**上限，包含失败/中断重试和计划中的零点监测；每批/每次启动既有扣零与参考轻触另外记录在 baseline 中，不冒称没有这部分耗时。未完成的批次不会当作完整 B 评估。

## 默认达标与结论范围

每个 B 至少 12 条正式扫描、3 条正常、3 条需恢复、3 条有回执的成功恢复；调用召回 ≥80%，正常不误调用 ≥90%，恢复成功率 ≥80%，退出召回 ≥80%，拒绝率 ≤20%，不允许提前宣称成功。必须有达标/未达标窗口，未知预测不能算成功，录制与人工标签必须齐全。开发 B 通过后，保持同一模型做 24 条独立扫描（另有 2 次零监测）。

接触 skill 达标与后续夹紧/提起成功率分别报告。默认 `require_task_success: false` 只停止接触 skill 研究；要以整段瓶子任务成功作为停止标准，**初始化前**设 true（默认整任务成功率门槛 80%）。报告不会把夹紧未达力改写成接触未恢复，也不会把接触达标描述为主模型完整任务已验证。

这些是当前固定场景和测试点的试验门槛，不是统计置信证书，不证明连续全区间、白绿跨瓶或跨传感器通用。接入主模型真机推理时仍需使用对应新模型与同一 target_definition_id、原 scheduler 的暂停/恢复接管约定；本入口 B 验证复用采集任务的后续夹紧与提起动作。
