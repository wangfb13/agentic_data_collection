## 如何读计划

- `facts.amplitude_coverage` 统计每个方向上的终端实测坐标。每箱默认至少有两条独立试次对目标消费者的有效结局，成功和失败都算。箱宽为 C5 实测分辨率和已声明标称步长的较大值。当前 r/h 没有标称步长，直接使用 C5。同一试次同一箱只投一次覆盖票。
- 每侧从参考向外取第一个连续缺口。开放缺口按最近连续覆盖的外缘倍增，内部出现已覆盖的远端箱时二分细化。箱沿用 H4 的内开外闭规则，零可支持两侧第一箱；每侧只产生一个候选。覆盖穿过的区间不等于成功范围。
- `probe_amplitude` 的 `amplitude_target.mm` 是本次放置参考下的终端坐标。轻、重瓶各一次，从首次接触的实测坐标算单轴位移。缺少坐标、方向相反、动作超限或重触未进入该缺口时，记录具体原因。下游和统计都使用实际观测。直接在该区域准备起点并交接的对照使用 `collect_outcomes`，动作数组为空。
- `facts.terminal_based_direct_boundary` 打开后，`direct_boundary` 描述到达某实测位置后交给该消费者的结局。每个消费者取它自己对应的终端。策略和专家边界保留起点语义。结局已测但坐标缺失的窗口保留在来源总数中。独立 B 数据继续封存。
- `director.score_based_axis_choice` 会枚举各轴各方向合法的单轴方案。排序先比较原 D5，随后比较候选触达的缺口宽度、是否为上一轮未选的轴，最后才使用已启用的方向先验。完全等价时用稳定摘要复现选择。缺 NeedAction 时在外侧缺口提供探测和直接交接候选；缺 Ready 时采用已覆盖实测位置中 Ready 后验下界最高的点及其条件。重复测量可以因其自己的证据缺口独立胜出。
- 当前轮结果见 `rounds/round_*/round_report.json` 的 `terminal_sources`。查看选择经过时打开同目录 `plan.json` 的 `decision.selection_audit`，其中包含候选计划、D5 分数、不可用原因和实际起作用的决胜条件。各开关和阈值见 `configs/p3_v5_manual_lift_h1214.json`。
