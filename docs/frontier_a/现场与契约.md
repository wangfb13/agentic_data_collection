# 白瓶 a 轴：从起点到结局的恢复边界实验

实现名为 max_expert_demonstration_finder。它维护自己的轮次和 SQLite 账本，不进入旧 campaign 的 planned 采集队列，也不借用最终 B 的 frozen 状态。**实验要比较的是一个冻结系统的能力，不是软胶或瓶子的物理极限。** 本次没有启动设备。

## 冻结和现场准备

1. 固定一种消费者和目标。默认资产是 `outputs/local_contact_a_v1` 的 **ForcePolicy 接手且确认力控就绪 L1**，不是“提起成功”。若做 fixed5，要使用按该目标训练、有相同固定参考、匹配 fixed5 版本与闭合协议的图包；不能改一个目标名字复用 L1 模型。单轮固定质量、摆放组、接近方向；轻重白瓶分组分别开轮。
2. 把 `skills/contact_position_a/frontier_config.json` 复制到实验目录，填入这个机器的实际 `station` 调查文件、工具/传感器版本、专家或驱动。**不要用 offline_fixture，也不要让新机器回旧绝对 T0。** 现场仍需确认整个张开夹爪和退让路径在已测的安全盒内，核对当前 TCP、指序、轻触协议、消费者身份。
3. 新位置的标准接触见证只为受控实验提供度量：在同一有效摆放上经确认标准抓法记录一次基准，然后用实际 TCP 沿本次工具 a 的投影测初始手偏移。也可使用独立测量或夹具。准备和首次轻触分别记录时间与测量；碰动后弃用旧基准。若由现场人员发现而非设备回报，用 `frontier --db … invalidate-basis 基准摘要 --reason 现场记录编号` 登记，此基准今后不能再产生有效标签。自然部署完全不需要这一步；没有真值也不妨碍自然技能推理。
4. 先选具名专家，例如使用既有受保护控制器的人类操作者，配置 id、version、source、observations、allowed_actions（首版仅 tcp_translation_a）及 stronger。没有专家时，默认生成待处理请求；`next --search-without-expert` 可以显式单独搜策略和 direct，不会伪造专家数据。更强专家的成功仅作为单独存在证据。
5. 根目录以下命令新建实验轮，保存打印的 ID 后续一直复用。实际运行前不要反复 init。默认每轮实物尝试上限 60，项目总上限 180，探索每点 3 次；这些是预算，不保证够做确认。示例只每次外扩最多 5 mm。准备上限 10 mm、恢复单步 10 mm、累计 20 mm、至多 2 步/60 秒。参数取自独立配置并与执行包络再次校验。

```bash
CFG=outputs/frontier_a/station_run.json
DB=outputs/frontier_a/white_light.sqlite
F=(bash run_on_5090.sh frontier --config "$CFG" --db "$DB")
ROUND=$("${F[@]}" init)
"${F[@]}" status "$ROUND"
"${F[@]}" next "$ROUND" --out outputs/frontier_a/next.json
```

默认模板未设置 station/driver/expert，适合审计，无法直接驱动设备。确认现场适配后，现场人员可检查 next.json 中的角色、偏移和轮次，再运行 `"${F[@]}" run-one "$ROUND" --choice outputs/frontier_a/next.json --real`。每次选择绑定账本修订，完成后旧文件不能再送一遍。另可在探索期用 next 的 `--agent` 让仓库 provider 在相同事实、合法选项、预算下选择；它不写标签、不发动作，不能改确认计划。

## 三种试验及采集接口

- **direct_baseline**：独立准备、真正首触、零位置修正、执行本轮消费者。direct 的交接决定不记作模型预测。
- **policy_frontier**：相同条件另开独立试次。调用冻结的 SymbolicRecoverySkill / ContactPolicy、decide_local；Unknown 原因原样保存。局部命令为 tcp_translation_a / tcp_at_action_start；动作通过 local_motion.recover_once，回执计算首次接触至重触的净修正，不是退让长度。
- **expert_recovery**：独立试次，具名专家在执行前提交决定，逐步记录实际“前状态、命令、实测回执、后状态”和实际消费者证据。人工帮助策略后取得成功不算自主策略成功。

现场有两个连接方式，都要求真实设备证据：

1. **持有 V4 控制权的驱动**：config.driver 指向现场 Python 文件，轮次固定其哈希。提供 `open_controlled_port(manifest)`；构造和 identity/verify 不动设备。返回对象须提供 `identity()`（survey_id、reference_digest、sensor_version、tool_version、consumer、condition），`expert_identity`（没有可为 null）、`now_ns()`（与轻触相同时钟）、`prepare_measured(req)`、`touch_once(req)`、`test_consumer(req)`、`bind_runner(req) -> (backend, runner)`、`deadline(seconds)`、`record_retouch(req,status,probe,row)`、`stop_and_close()`；配置专家时另有 `expert_decision(...)`。准备负责受控扰动、对齐测量、记录复位和标准见证成本；消费函数只运行指定版本的消费者。用 `skills.contact_position_a.frontier.controlled_window` 把 V4 本次 touch 连到观测；传入已有 observation 可避免重新消费同一窗口。无接触时仍有 observation，无须图节点。bind_runner 必须持有真实独占控制权、使用已验收站位及相同参考；在新角色的独立适配实例上执行，不能冒用自然部署的 role，也不能用旧 bounds.a 注入扰动。超时、异常时由驱动停止和释放控制权，禁止隐式继续任务。
2. **仅记录由外部现场人员执行的专家示范**：config.expert_exchange 指到已准备好的记录交换目录。外部记录器写 `station_identity.json`，含上面 identity 的全部字段及 expert。程序在准备前创建 attempt，逐阶段写 `<attempt>/prepare.request.json`、`touch.request.json`、`action_i.request.json`、`post.request.json`。它们是记录票据，不是机器人指令。对每个票据，现场记录器完成本次真实采集后原子写同名 `.reply.json`。专家事前写 `decision_i.json`，含本次 attempt_id、observation_id、expert_id、expert_version、state（Ready/NeedAction/Unknown），NeedAction 另需 delta_a_mm。重触要保留双侧触觉、实测动作和新观测。工位控制器仍负责实时力、速度、观测新鲜度、租约和急停；记录入口不具备越过这些检查的权限。旧的普通成功日志不能事后命名成这种示范。

**现场仍缺什么：** 本次没有该新机器签核的站位文件、指定专家、独立测量文件，也没有在真机控制权/看门狗和消费者回执上验收上述站端驱动。仓库实现了调用方、V4 局部决策与动作对接、真实回执读取和专家记录端；未替现场提供一份假标定或虚构一个已测试的硬件服务。先在不发动作的条件下验证传感时钟、文件回执与支持域，再做一组原位置的 direct 与 expert，最后做冻结 policy。不要先扩大动作边界。

## 数据与统计契约

- **frontier_round**：内容摘要、图与支持集/噪声摘要、模型/代码/驱动文件指纹、固定参考、工具轴、协议、消费者和条件、预算、阈值、父轮。数据库保存 manifest、阶段、预注册计划、pending attempt。轮内不重训，旧 campaign 的独立 B 状态和退款逻辑都不参与。
- **episode**：从准备之前的唯一 attempt 开始。请求偏移、准备实测、首次尝试实测、模型估计分字段；首次接触状态、首个有效节点、终端窗口不互相替代。每步调用以 attempt/command_id 幂等记录意图与回执。人介入、设备异常、未知消费者和动作超预算均保留。传感/程序故障属于现象；没有验证过的根因保持空。graph.unreachable 仅指已测试动作下未找到路径。
- **证据文件**：每个物理回复给出 attempt_id、command_id、raw_source（回复 sidecar 的绝对文件名）、physical_interaction 和 activity_counts（实测的 standard_measurements、preparation_moves、resets、touches、actions、expert_interventions）。准备回复带 prepared、condition、independent_trial_unit、timestamp_ns 和独立 measurement；独立试验单元不能被重复用于确认。轻触回复带 observation；post 回复带 post_condition 和原评估器要求的 consumer_outcome（事件、控制器版本及参数）。未验证的完整任务 L3 不填。回复 sidecar JSON 的 reply 等于回复去除 raw_source，acquisition_files 为真实采集文件的 path 和 sha256。对大 H5 可引用从原始流导出的不可变事件片段。站端以临时文件加 rename 发布，不能事后覆盖。
- **毫米证据**：measurement 为 `{record,evidence_id}`（用 evidence.label_record 生成）；record 需携带 reference_digest、target_definition_id、source、axis_sign、unit、phase、timestamp_ns、valid、object_moved、uncertainty_mm、raw_source。独立仪器提供 instrument_id、calibration_id、reading_mm；共享标准提供经确认的 standard_witness、basis_id、placement_id、tcp_mm。测量 sidecar 的 measurement 等于 record 去除 raw_source，并引用原采集文件及摘要。首触的测量时间必须与该观测一致；准备不能补首触。无法核验的标签不参与毫米统计。测得的偏移及其误差带须能放入同一个带容差的格点；仍输出原始实测值。
- **分母**：输出全部已结束初始尝试（另列 pending）、已触发物理交互、双侧有效首触比例、在有效首触／在首次 NeedAction 下的条件结果、可信首触毫米覆盖率、另列按准备坐标统计。整体成功表示该角色在预算内完成且通过同一实际消费者检验；真实消费者尚未执行时仍为 null。策略从 Ready 直接成功计入该策略的整次结果，不能当作实际纠正见证。
- **确认统计**：探索按符号分侧、局部有序括区才选中点；出现反转先增加重复并细化网格。输出最远观测成功、按分辨率从 0 连通的已确认格点、初步括区、非单调区和未知区。端点成功标 envelope_limited。独立确认先锁点、角色及 N，再用新尝试；仅到固定 N、独立单元齐全且首触落入预定格点才给双侧 Clopper–Pearson 区间，按两角色×点数作 Bonferroni 校正。探索的区间只作描述。确认阶段不补看起来差的点、不替换无标签的槽位、不把未知当到达极限。
- **算子**：probe_recovery_frontier、repeat_recovery_cell、refine_recovery_bracket、request_expert_recovery、validate_recovery_frontier、retrain_from_frontier；事实由 episode 和统计计算，含证据 ID。原 densify 的 3 点契约不变；单点试验由 frontier 自己验证。模型不可执行时不允许发 policy 动作。
- **中断**：DB 在发物理请求前先记意图。已开始而未收到回执时不能自动重发；先核查工位与原始文件。用 `reconcile ROUND ATTEMPT --station-replies replies.json --reason 原始记录或检查说明`，只导入本 attempt 已登记命令的回执，然后收尾，不继续发动作。若无回执，缺失仍显式保留；计费次数不退。真实已确认交互和“可能已发出”的保守预扣分别统计。复位、标准见证必须由站端纳入 activity_counts；没有回执的成本明细标未知，不能事后猜测精确次数。

## 训练与独立确认

`"${F[@]}" confirm "$ROUND" --points -5 0 5` 是语法示例，实际点必须已经探索。每个点有独立 direct、policy 两组；示例三个点、每组 30 次，需要 **180 次新的确认尝试**，不含探索。默认单轮预算不足以完成这种计划，保留 inconclusive；若项目需要整段认证，应在开轮前决定可承担的样本数、点数与预算。填满一个格点不证明其间所有连续位置。

用 `"${F[@]}" report "$ROUND" --out outputs/frontier_a/result.json` 保存事实、逐条 episode、各分母、专家集合和成本。关闭轮次后，`"${F[@]}" retrain "$ROUND" --out outputs/frontier_a/new_assets_v2` 重建并核对父模型支持集与图，加入合格探索期 direct 结果和同能力专家的实测前—动作—后窗口，训练图的 Ready／动作／动力学与噪声。这不会把专家动作改成偏移真值；offset_servo 如使用仍保留其独立几何估计器。没有合格专家轨迹不训练。确认数据以及最终 B 不进入训练、噪声或选点。命令生成新模型和新的冻结 round_id；在相同条件下重新探索并预注册新的确认试次。使用 `compare OLD_ROUND NEW_ROUND`；只有共同预注册的格点在跨版本校正后满足“新版达到目标、旧版低于目标”才报告确认改善。旧版证据不足不等于失败。
