# 当前药瓶的无标记定位：图像准备、标定与现场验收

本入口用于当前绿色瓶身、白色瓶盖的已知药瓶。运行时不要求在瓶子上贴 ArUco 标记。图像先产生绿色瓶身候选区域，再结合实测外形、桌面与相机几何估计位置；之后复用已有示教边界和开爪运动检查。

本轮开发只进行代码和离线测试，没有启动机器人、采集新的实时图像或发布真实运动指令。下文的现场命令与验收是后续操作说明。

## 1. 本版解决什么问题

- 对象是同一种已知药瓶，竖直放在已标定的水平桌面上，瓶身外形在模型支持范围内。
- 视觉估计的是瓶身轴心在桌面上的 **X/Y 位置**。底部 Z 来自桌面高度，竖直轴来自任务约束，不是图像独立测得的自由三维位姿。
- 轴对称轮廓不能确定瓶子绕自身轴线的转角。输出中的朝向是计算坐标系约定，不能理解成已识别瓶盖文字或瓶身实际 yaw。
- 机器人仍可按示教参考修正三维位置，但视觉没有因此获得任意高度、任意倾斜或悬空瓶子的定位能力。
- 当前定位使用颜色和轮廓。颜色相似的对象可能混淆；需要限定单目标工位，并用实际负样本验证，不能把颜色匹配当物体身份认证。
- 保留完整工具包络、桌面/瓶体与拟议路径检查、标定与示教参考版本绑定、图像时间新鲜度、开爪/无接触和停靠臂检查。仍然只做开爪平移，不夹紧、不提起。

旧 ArUco 配置不会自动变为无标记配置。已有工作空间边界可以作为新版本的输入复用，但瓶子参考位姿、目标关系和视觉标定绑定需要按新定位模型重新建立，不能只改 schema 或复制旧哈希。

## 2. 需要准备哪些图像

先保留相机的原始分辨率、颜色、曝光/镜头设置和时间信息。不要先裁剪、缩放后再套用原相机内参。程序读取普通图像文件后会按其接口转换为 RGB；手工处理图像时应记录实际色彩格式。

| 图像组 | 要拍到什么 | 用途 |
|---|---|---|
| 清晰正样本 | 当前药瓶，绿色瓶身尽量完整、清晰；覆盖允许工作空间中的近/远、左/右位置及实际观察姿态 | 建立外观模型并检查视角覆盖 |
| 光照变化 | 实际会遇到的曝光、阴影、反光条件，不把极端或失败画面删掉 | 检查颜色范围是否稳定 |
| 负样本 | 空桌面、没有瓶子、其他绿色物体、多个相似瓶子及背景杂物 | 检查误检与多候选拒绝 |
| 遮挡和截断 | 夹爪挡住瓶身、只见半个瓶子、瓶身贴图像边缘 | 检查不能可靠定位时是否拒绝 |
| 独立定位验证 | 瓶子位于多个独立测得的位置，图像与相机所在腕部 TCP 同时记录 | 验证毫米尺度、方向与实际位置误差 |
| 标定图像 | 相机内参所需的临时标定板，以及手眼标定所需的多姿态记录 | 求相机几何；这些标定板不需要留在瓶子上 |

两路腕相机需要分别准备与各自标定匹配的样本，不能把左腕图像配到右臂 TCP。当前两路 RGB 图像不是自动可用的双目深度输入；每个视角要满足自己的定位条件。

历史记录中，右腕可以看到较完整的绿色瓶身，左腕在部分位置被夹指遮挡。这样的历史图像可以用于外观与拒绝机制检查；没有相应实测相机标定和独立位置真值时，不能据此报告毫米定位准确率。

本次历史图像离线回放记录在仓库的 `outputs/markerless_20261108/historical_segmentation_report.json`：右腕旧图得到一个有效绿色候选，面积为 **10850 像素**，检测框 `[x, y, width, height] = [910, 785, 112, 127]`；左腕旧图出现多个绿色候选，程序拒绝选择目标。这证明了这两张图上的二维分割与拒绝路径，没有给出瓶子的毫米坐标，没有完成独立定位验收，也没有驱动机器人。

### 2.1 人工 mask 如何准备

外观训练需要与原图同宽高的单通道 PNG：白色/非零为前景，黑色为背景。

- 前景选确定属于绿色瓶身的像素；不包含白盖、橙色夹爪、桌面或背景。
- 外观训练可以选清晰的内部绿色区域，以避免把边界混色误当瓶身颜色。这个训练 mask 不等于后续完整轮廓的真值。
- 检查几何拟合时，应另准备完整可见绿色区域的人工轮廓标注，并记录是否存在遮挡。被夹爪挡住的部分不能凭想象补成真实观测。
- 如果图像有大片强反光，应保留原图，并在独立验证中检查其分割是否碎裂或漏检，不要只挑易识别样本。
- 图像裁剪、缩放或旋转后，mask 必须一起变换，并使用对应相机参数；首版优先直接使用原图。

## 3. 需要补齐的几何与标定

### 3.1 药瓶外形与桌面

`body_profile_mm` 描述被颜色分割的绿色瓶身：每个点为 `[距桌面的高度, 该高度处的外半径]`，单位均为 mm。它不是图像像素尺寸，也不是瓶盖外径。

应实测绿色区域的底部、顶部及半径有变化的位置。若瓶身略带锥度，应把外形变化记入模型；不能为了拟合某张图而随意改变物理尺寸。当前模型接受 2 至 5 个高度递增、半径为正的截面，要求它们描述凸的轴对称实体，不支持凹肩或任意瓶身网格。

需要测量桌面在机器人基座坐标系中的高度。桌面倾斜、瓶子倾倒、瓶子被提起、垫了东西或换了不同尺寸的瓶子，都改变当前模型的前提，应停止使用原版本并重新检查。

白盖可能遮挡绿色瓶身上缘，尤其在俯视角下。对于当前有外凸白盖的药瓶，应实测并配置 `cap_profile_mm`：同样以 `[距桌面的高度, 外半径]` 表示，盖底不能低于模型绿色区域顶部。它只负责预测白盖挡住了哪些绿色区域，不把白盖当绿色前景。该遮挡模型要求相机中心高于完整瓶盖；其他观察高度会拒绝，不支持由这一模型推断任意视角的自遮挡。

实际绿色区域是否符合配置外形，需要用现场图像独立验证；不能用形态学操作随意补全夹爪等未知遮挡物挡住的轮廓，再把结果当作可靠几何观测。轮廓误差较大时应保留拒绝结果，调整允许的观察条件或外形模型，而不是直接放宽误差阈值。

### 3.2 相机内参、畸变与手眼

1. 为使用的相机与实际图像分辨率求内参和畸变。`camera_model` 必须明确选择与实际标定一致的 `pinhole` 或 `fisheye`，不能根据数组长度猜测镜头类型。
2. 针孔模型使用其对应畸变数组；鱼眼模型使用 OpenCV 鱼眼定义下的四项畸变参数。两套参数不可互换。
3. 对每个腕部相机标定 `T_tcp_camera_mm`，明确 `mount_tcp_side`。变换 `T_A_B` 把 B 坐标中的点变到 A 坐标中；矩阵的平移分量使用 mm。
4. 用未参与标定的位姿和独立已知位置检查方向、尺度和误差。低重投影误差不能单独证明机器人坐标转换正确。
5. 检查图像与对应腕部 TCP 的时间差。主机接收时间不是硬件曝光同步证明；首轮采用停稳取像，并量化延迟和允许时间差。

本阶段真实入口使用左右腕对应的实时 TCP；固定相机模式只用于离线验证。相机临时停住不能代替固定相机的独立标定与安装绑定。

### 3.3 既有站点与几何参考

仍需有效的真实站点配置，以及原有 TCP、夹爪毫米开度、工具外形、停止、力控和命令所有权检查。`setup --check-only` 只读；普通 `setup` 可能执行运动和力控验收。

`geometry_reference_tcp_mm` 必须正确对应旧几何模块的瓶体参考，与无标记定位给出的参考瓶位属于同一场景。绿色模型只用于定位，碰撞检查继续使用既有完整瓶体和工具外形；不能把缺失的瓶盖或手掌碰撞体删掉以通过规划。

核对两套模型时，应把旧碰撞模型的轴线、各段高度与半径变换到机器人基座系：轴线应与视觉参考瓶位的竖直轴对应，碰撞圆柱包络应覆盖实测瓶身和白盖，碰撞桌面边界不得低于物理桌面。更保守的碰撞半径或桌面上界可以保留；不能让错误坐标偏移、过小半径或遗漏瓶盖使检查误判为无碰撞。

程序会在无标记规划前检查上述对应关系：拒绝碰撞轴线的水平偏移或倾斜、低于视觉物理桌面的碰撞边界，以及不能覆盖视觉瓶身/瓶盖的碰撞包络。覆盖检查按连续高度区间进行，包括圆柱分段间的空隙；不能只让上下两个端点看起来匹配。碰撞包络可以比视觉实体更保守，但名义尺寸必须完整覆盖，不能借用轴向不确定度来掩盖遗漏部分。遇到这些拒绝时应回查实际测量、坐标转换和配置版本，不应删掉保护检查。

既有配置的 `safety.margin_mm` 必须至少覆盖 `fit_limits.max_position_uncertainty_mm`；规划还会拒绝缺失、非有限、负值或超过这一上限的观测 `position_uncertainty_mm`。这只是把视觉拟合的局部图像误差上限纳入现有碰撞余量的最低要求。相机内参、手眼、瓶体尺寸、桌面高度等系统误差仍需由独立位置验收量化，并在现场总误差预算中计入额外余量。不能为了通过此检查而任意降低视觉误差阈值；改变既有保护余量后，也必须重新检查站点、示教边界和路径的有效性。

外观模型、相机标定、药瓶尺寸、桌面高度和参考关系均需保存版本。改变其中任何一项后，应重新生成标定内容哈希并建立对应的示教参考。代码中的哈希用于防止版本混用，不是现场精度证书。

## 4. 先离线构建和检查

以下命令在 `6f5090` 的 `/home/dm/DM_das/bottle_grasp_experiment` 中执行。所有输出使用新路径；不会通过这些离线命令连接相机或机器人。

### 4.1 外观模型

准备前景 mask 和说明其来源的 `appearance_evidence.json`，然后运行：

```bash
.venv/bin/python vision_stage1.py build-appearance \
  --image measurements/bottle_reference.png \
  --mask measurements/bottle_foreground_mask.png \
  --target-id current_green_bottle \
  --evidence measurements/appearance_evidence.json \
  --out measurements/bottle_appearance_v1.json
```

合成图像必须显式使用 `--simulated`。真实历史图片只能证明该图片上的外观处理，不会自动成为现场验收。

外观参数可通过命令支持的 `--settings` 文件显式配置。应记录为什么修改阈值，并保留失败样本；不要为了把多个绿色物体压成一个结果而只选择最大连通区域。

如果设置了 `search_roi_xywh`，颜色候选检查只在该图像区域内进行；它不能证明区域外没有相似物体，也不能代替机器人工作空间或碰撞检查。

可额外提供 `--background-mask measurements/bottle_background_mask.png`，标注同一张图中确定不属于绿色瓶身的像素。背景 mask 与前景 mask 不得重叠。若背景大量匹配目标颜色，构建会拒绝；没有背景标注时，程序不声称已经验证背景可区分性。`--evidence` 是非空 JSON/YAML 对象，应记录图像来源、相机、拍摄条件和人工标注人/版本等实际信息。

### 4.2 只检查分割，不产生机器人目标

```bash
.venv/bin/python vision_stage1.py detect-bottle \
  --image measurements/bottle_check.png \
  --appearance measurements/bottle_appearance_v1.json \
  --out outputs/bottle_detection_v1.json \
  --mask-out outputs/bottle_detection_v1.png
```

这一步只给像素区域、候选和拒绝原因。检测框、mask 或 `valid=true` 不代表已经知道瓶子在机器人坐标系中的位置。

`--mask-out` 可省略；检测拒绝时只保存报告，不生成成功候选 mask，进程返回码为 `2`。报告中 `metric_pose_available=false`、`hardware_connected=false` 表明这个入口的范围。

建议逐张检查正样本与负样本，观察是否混入夹爪、白盖或背景，是否存在裁剪/遮挡，以及多个候选是否被拒绝。

### 4.3 加入实测几何后离线预览

无标记标定使用 `schema: markerless_bottle_calibration_v1`，主要内容包括：

| 字段 | 来源 |
|---|---|
| `target_id`、嵌入的 `appearance_profile` | 上一步外观模型及其内容哈希 |
| `camera_name`、`camera_model`、`image_size_wh`、`camera_matrix`、`distortion_coefficients` | 对应相机的实际标定 |
| `camera_mount`、`mount_tcp_side`、`T_tcp_camera_mm` | 相机安装与对应腕部手眼标定 |
| `model.body_profile_mm`、`model.cap_profile_mm`、`model.table_z_mm` | 绿色瓶身、外凸瓶盖与桌面实测 |
| `fit_limits` | 预先定义的 XY 搜索范围、轮廓/IoU、不确定度、面积与可观测性门槛 |
| 观测与位姿时间限制 | 记录时序和延迟验证 |
| `simulated`、`evidence` | 数据来源、站点身份与各项标定记录 |

模型参数和矩阵由实际测量、标定求解产生，不能填写猜测值。新的无标记方案不需要 `marker_id`、`marker_length_mm` 或 `T_marker_bottle_mm`。

完整模板在 `docs/markerless_calibration.example.yaml`。模板刻意使用 `null`，直接加载会被拒绝。复制到新的测量文件，逐项补齐；`appearance_profile` 必须嵌入 `build-appearance` 输出的完整对象，不能填写路径。`evidence.station_hardware_hash` 必须对应后续使用的真实站点文件。`model.table_z_mm` 是物理桌面高度，示教/碰撞配置中的桌面高度可以是保守上界，两者含义不同。

填完模板后，可用下面的纯离线脚本嵌入外观文件、规范化校验并生成最终 JSON。它不连接设备；任何尚未填写的必要测量参数会使校验失败。

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path
import yaml
from bottle_scan.vision_localization import validate_calibration

draft = yaml.safe_load(Path("measurements/markerless_calibration_draft.yaml").read_text())
draft["appearance_profile"] = json.loads(Path("measurements/bottle_appearance_v1.json").read_text())
calibration = validate_calibration(draft)
with Path("measurements/markerless_calibration_v1.json").open("x") as stream:
    json.dump(calibration, stream, ensure_ascii=False, allow_nan=False, indent=2)
    stream.write("\n")
PY
```

规范化过程生成 `calibration_sha256`，不需要手工拼接哈希或额外 seal 命令。它只验证配置结构和一致性，不能代替 `evidence` 所指的实际测量与验收。

准备新的示教参考绑定后，可以沿用已有 `preview`：

```bash
.venv/bin/python vision_stage1.py preview \
  --workspace outputs/markerless_workspace_v1.json \
  --calibration measurements/markerless_calibration_v1.json \
  --image measurements/bottle_check.png \
  --pose measurements/bottle_check_pose.json \
  --out outputs/markerless_preview_v1.json
```

位姿记录继续包含相机挂载臂的 `T_base_tcp_mm`、准备运动的 `current_tcp_mm`、`image_timestamp_ns`、`pose_timestamp_ns`、`now_ns` 与 `pose_tcp_side`。历史记录使用原单调时钟中的评估时刻，不能把旧图像时间改成当前时间来授权实时动作。

## 5. 后续现场操作

完成真实站点与视觉标定之后，原 `teach --real` 和 `commission --real` 入口根据标定 schema 使用无标记定位。步骤和边界文件约定仍见 `docs/VISION_STAGE1_GUIDE_zh.md`，但应使用新的无标记标定文件与重新绑定的参考。

`teach --real` 本身只读：你遥操作到边界、开爪目标位和观察位，停稳后记录。它不会替你移动。只有 `commission --real` 会在现有门禁和逐步 `MOVE` 确认下执行开爪平移。

因为定位依赖可见的绿色轮廓，观察位必须让目标轮廓满足当前模型要求。若夹爪接近后挡住瓶身，程序应拒绝继续定位；本版不会自动寻找新视角或使用隐藏的形状补全来继续运动。

## 6. 验收与报告

先写下试验点、独立测量方法、误差阈值和通过标准，再执行；开发/调阈值的图像与最后验收图像分开保留。

| 验收项 | 必须检查的结果 |
|---|---|
| 正样本覆盖 | 允许距离、位置、观察姿态与实际光照下的检测率及拒绝率 |
| 负样本 | 无瓶、其他绿色物体、多候选不能被静默认作可靠目标 |
| 轮廓完整性 | 遮挡、截断、错误尺寸、瓶盖遮挡或明显模型不匹配时拒绝或明确限制适用范围 |
| 毫米定位 | 与独立实测轴心位置比较，分别报告 X/Y 误差；不把固定桌面 Z 计为图像估计成功 |
| 模型前提 | 倾倒、离桌、不同瓶型不得被宣称支持；部分异常可能产生相似投影，必须维持实际工位条件 |
| 坐标与时间 | 左右腕配对、相机模型、分辨率、手眼方向、时间新鲜度与单位一致 |
| 误差与保护余量 | 已有碰撞余量至少覆盖配置的局部视觉误差上限，并依据独立位置测量为标定、尺寸、桌面等系统误差另留余量 |
| 运动保护 | 固定世界边界、全路径检查、累计位移、开爪/无接触与停靠臂变化拒绝仍有效 |
