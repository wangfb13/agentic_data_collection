# Agentic 自适应探索范围与采样间距

本说明对应 2026-10-30 的自适应设计功能。日常命令、账号连接和现场操作见 [Agentic 操作指南](../AGENTIC_GUIDE_zh.md)。本功能使用独立 `agentic` 入口，复用原 E1/E2 执行流程；原 `e1e2`、`analyze_e1e2` 和 setup/run 向导不变。

## 1. 自动变化的设计与固定限制

程序保存两层范围：

| 项目 | 含义 | 是否自动变化 |
|---|---|---|
| `scope.min_mm / max_mm` | 本轮不可越过的硬范围，默认 −25 至 +25 mm | 否；创建 campaign 时固定 |
| `design.min_mm / max_mm` | 当前实际研究的范围，包含零点且位于硬范围内 | 可根据选定候选向单侧扩展 |
| `design.step_mm` | 当前设计的名义采样间隔 | 可局部细化，每轮减半至配置下限 |
| 固定 T0 | 整个 campaign 的抓取基准位置与朝向 | 否 |
| 力、开度、速度和运动限制 | 原 E1/E2 的执行条件 | 否；Agent 没有修改权限 |

硬范围沿用原抓取/纠正目标相对 T0 不超过 25 mm 的限制。退让和提起仍分别受原限制，TCP 高度下限继续独立检查。硬范围内的目标不一定能执行，也不意味着程序必须探索到硬范围两端。

程序不会为了排除失败数据而自动收缩当前探索范围。因高度限制跳过、目标力未达到或接触失败造成的停止，分别保留原原因，不改写为“已经找到触觉能力边界”。

默认关键设置如下；这是完整配置中的相关字段：

```yaml
scope:
  adaptive: true
  min_mm: -25.0
  max_mm: 25.0
  initial_min_mm: -2.0
  initial_max_mm: 10.0
  step_mm: 2.0
  min_step_mm: 0.5
  allow_expand: true
  expansion_step_mm: 5.0
validation:
  adaptive_scope: true
  points: 5
  reps: 4
budget:
  max_trials: 120
```

## 2. 如何决定初始范围

导入历史数据后，程序先检查数据协议、固定 T0、触觉和力定义等兼容性。用于初始化的是 **A 的有效初次 PROBE 且有实测 TCP 来源的位置**，不是将历史命令中写过的全部 offsets 都视为有效范围。

有足够有效档位时：

1. 取固定硬边界内已有有效 A 档位的最小值和最大值，并保证当前范围包含 0。
2. 计算这些不同档位相邻间隔的中位数，作为初始名义采样间隔；不低于配置的最小间隔。
3. 将结果和来源写入 `campaign.json` 的 `design`，在 `design_history` 中记录 `initialize`。

没有足够有效实测 A 起点时，使用冷启动范围 −2 至 +10 mm、名义间隔 2 mm；如果通过 `--scope` 缩小了硬范围，起点也相应限制在其中。

B 的数据用于诊断纠正效果、重抓、过冲等，不用来代替 A 映射标定。只有 B 历史记录时，仍可能需要先采 A。

初始范围和档距以终端打印及 `design` 实际保存的值为准。历史命令曾包含 −20 至 +20 mm，不代表程序一定会从这个完整区间开始；无接触、贴边、无效或缺少实测位姿的数据不能被当成有效标定证据。

## 3. 每轮可以选择什么

数值模块生成带有证据、理由和预算的合法候选，Agent 选择其中的候选 ID。本地检查通过后，程序才锁定本批点位并执行。Agent 不直接生成任意 ROS 命令，也不能任意修改安全数值。

| 候选 | 什么时候使用 | 对设计的影响 |
|---|---|---|
| 普通补采 `sample` | 当前范围存在缺点、覆盖不足或需要当前模型的 B 效果反馈 | 范围和名义间隔不变 |
| 重复 `repeat` | 同档触觉波动大，或实际 TCP 档位分离不足，需要先确认噪声与位置可分性 | 范围和名义间隔不变 |
| 局部细化 `refine` | 留出误差、局部非线性、接触转变或 B 反馈指向某个待解释区间 | 在局部加入测点，名义间隔减半，默认最小 0.5 mm |
| 左扩展 `expand_left` | 左侧边缘已有充分有效、实测且成功的 A 证据 | 左界向外最多 5 mm，右界与间隔不变 |
| 右扩展 `expand_right` | 右侧边缘已有充分有效、实测且成功的 A 证据 | 右界向外最多 5 mm，左界与间隔不变 |
| B 测试 | 当前触觉模型已有可用验证证据，需要检验纠正结果或比较允许的增益 | 使用冻结于本批的模型与增益，不向纠正器提供试验 δ |

细化根据需要发生在局部区间，并不是每轮都把整个范围按新间隔重新采一遍。例如名义档距 5 mm 可以减为 2.5 mm，随后再根据新证据决定是否继续；不能把这种候选变化直接解释为已经实现 2.5 mm 的测量精度。

扩展需要该侧边缘的有效实测、双侧接触、达到目标力、提起并保持成功等证据，并包含轻重瓶。新批次会同时测新的外侧位置和原边缘位置。线性拟合的 R² 高本身不足以支持向外扩展。

新增位置和原边缘对照点先各做 2 次（轻重瓶各 1 次），先取得新证据再决定是否重复；不会为了填满批次额度而在单个新位置直接做十几次。明确的噪声复测候选可以追加重复，仍受预算与重复上限约束。

已有接触失败、抓取失败或执行约束等记录会阻止向相应方向盲目扩大。执行跳过的数据仍参与诊断；它不能通过继续加密触觉样本来消除原本的高度限制。

## 4. 为什么有时重复而不继续加密

程序保持 **2 mm TCP 到位容差**。生成 1 mm 或 0.5 mm 的名义候选，不会自动把控制容差改小。

细化判断同时考虑：

- 相邻指令档位在实测 TCP 上是否真正分开；
- 每个档位的实测位姿重复波动；
- 两指触觉的重复噪声和等效偏移误差；
- 局部拟合偏差、接触转变和 B 的实际纠正反馈。

若新间隔会被噪声或位置波动淹没，程序优先提出重复和诊断，而不是不断缩小名义步长。重复受配置中的次数限制；达到限制仍不能区分时，报告证据不足，不把名义网格密度当成实际分辨率。

PROBE 时的实测 TCP 相对固定 T0 的位移用于分析实际到位情况。但瓶子若被推动，这个位移不再等于夹爪相对瓶子的真实偏移。倾倒、推动等记录不用于映射训练，现场复位与人工标签仍然必要。

## 5. 设计怎样保存和续跑

候选生成、Agent 选择和计划写入是分开的步骤：

1. 分析生成可选计划及其 `design_next`，并保存候选检查结果。
2. Agent 选择一个合法候选，说明理由。
3. 程序重新检查固定硬范围、单侧扩展幅度、细化步长、目标位置、模型版本及剩余预算。
4. 保存 `batch_plan.json`，同时将选定设计写入 `campaign.json` 的 `design` 和 `design_history`。
5. 执行这份已锁定的批次计划。中断续跑继续原计划，不因重新分析而临时改点。

只查看 `agentic plan` 不会执行候选，也不会把某个未选中的扩展提案变成当前设计。首次分析尚未初始化的 campaign 时，可以根据证据建立初始设计；此后设计变更随选定批次保存。

主要审计文件：

| 文件 | 作用 |
|---|---|
| `campaign.json` | 固定设置、当前 `design`、完整 `design_history`、预算与断点 |
| `analysis/latest.json` | 当前设计、固定硬范围、模型误差、质量与覆盖诊断 |
| `analysis/candidate_checks.json` | 合法候选、拒绝候选及原因 |
| `decisions/*` | Agent 当时读取的证据、候选和选择理由 |
| `batches/NNNN/batch_plan.json` | 当批点位、`design_before`、`design_after` 和选择来源 |
| `frozen.json` | 最终冻结的模型、增益、当前范围和验证点 |

## 6. 独立验证在冻结时定点

默认 `validation.adaptive_scope: true`，`points: 5`。模型和纠正增益冻结时，程序根据 **当时的当前探索范围**生成 5 个互不重复的位置，包含两端和零点，写入 `frozen.json` 的 `validation_offsets_mm`。

这些验证点在冻结后不再改变。验证采集的结果不会反过来改变本轮模型、增益、范围或验证点。

默认每个偏移的 A、B 各 4 次，轻重瓶各半：

- 5 个位置 × 2 个条件 × 4 次 = 40 次正式验证。
- `zero_every: 10` 时，另有 4 次零点监测。
- 总计预留 44 次，默认新增总预算仍为 120 次；历史种子不计入新增次数。

若配置改变点数、重复数或监测频率，预留次数会随实际计划计算，不应继续把 44 当作固定常数。

报告的 A/B 成功率和 Wilson 区间针对这些已测位置。**5 个点不能证明整个连续区间内每个位置都具有相同性能。** 冻结范围也不自动等于整个 −25 至 +25 mm 的硬范围。`complete` 表示流程完成；统计验收是否通过、证据是否不足，按报告中的独立结论判断。

## 7. 启动和旧 campaign 迁移

在 5090 项目目录，由现场操作员执行实机命令；无需新增自适应开关：

```bash
bash run_on_5090.sh agentic run --real \
  --seed-session outputs/e1e2_A_formal01 \
  --out outputs/agentic_adaptive01
```

可以增加同一固定 T0、协议一致的 B 历史数据：

```bash
bash run_on_5090.sh agentic run --real \
  --seed-session outputs/e1e2_A_formal01 \
  --seed-session outputs/e1e2_B_formal01 \
  --out outputs/agentic_adaptive_with_B01
```

如果只允许小范围研究，将硬边界限制在 −2 至 +10 mm：

```bash
bash run_on_5090.sh agentic run --real \
  --scope -2 10 \
  --seed-session outputs/e1e2_A_formal01 \
  --out outputs/agentic_adaptive_local01
```

`--scope` 在新的自适应 campaign 中表示硬边界。Agent 可以在其中改变当前范围和名义间隔，但不能越界。固定硬范围、预算或现场基准发生变化时应新建输出目录。

旧 campaign 使用原配置快照。快照没有启用 `scope.adaptive` 时，更新代码不会自动将它转换为自适应模式，也不会改写其旧验证计划。要采用新功能，创建新的 `--out`，通过 `--seed-session` 复用可兼容的旧数据。

新 campaign 建立后，暂停和续跑沿用：

```bash
bash run_on_5090.sh agentic resume --real --out outputs/agentic_adaptive01
```

只读查看设计和候选：

```bash
bash run_on_5090.sh agentic status --out outputs/agentic_adaptive01
bash run_on_5090.sh agentic plan --out outputs/agentic_adaptive01
```

## 8. 验证记录

5090 上新旧模块合计 **261 项离线测试全部通过**，包含范围/步长约束、实际位置不可分时不细化、噪声重复、失败边界、旧版兼容、预算、续跑和冻结后验证点不变。

只读分析现有 `e1e2_A_formal01` 后，当前数据自动得到起始范围 **−15 至 +15 mm、名义档距 5 mm**，并生成局部 2.5 mm 细化和噪声复测两类候选。这只是该批数据在当前规则下的提案，不代表它们已经执行或会固定照单执行；实际下一批由 Agent 选择。

所有联调均为离线分析或明确标记的模拟机器人，未执行实机动作。模拟采集结果不作为实机性能证据。

真实 ChatGPT 驱动模拟闭环已完成 91 次合成试验：初始 A → 右扩至 +15 mm → 细化到 1 mm → 细化到 0.5 mm → 左扩至 −7 mm → 达到本次测试的5批探索上限后冻结并做独立 A/B 验证。最终验证未宣称通过，报告保留失败点和证据不足结论。记录在 5090 的 `outputs/agentic_adaptive_llm_20261030/`。
