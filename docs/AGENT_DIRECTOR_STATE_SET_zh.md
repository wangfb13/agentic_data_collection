# a 轴：Agent 主导实验与可接受接触状态集合

新入口配置是 `config.white_bottle_a_20261110.director.loop.yaml`，对应
`config.white_bottle_a_20261110.set.skill.yaml`。这是独立版本，不修改旧实验标签、旧模型或正在进行的实验。

## Agent 决定什么

`planner.authority: director` 下，Agent 在初始化、A 采集后、联合训练后、B 评估后作出下一步决定：

| 决策 | 实际作用 |
| --- | --- |
| `collect_A` | 根据证据设计 a 轴位置与重复次数，采集新观测和标签 |
| `train` | 用当前开发数据同步更新调用、恢复和退出三个组件 |
| `validate_B` | 为当前可执行模型设计开发 B，验证调用、实际恢复和退出 |
| `freeze` | 固定当前模型，执行事先声明的独立 B 方案 |
| `complete` | 根据该冻结版本的独立 B 证据宣布本轮位置 skill 验证完成 |
| `review_labels` | 指出目标含义或标签冲突，等待真实观测复核 |
| `pause` | 说明证据、能力或实验预算不足，保留当前进度 |

训练通过不会自动进入 B；开发 B 通过不会自动冻结；独立 B 通过也需要 Agent 的结束决定。
程序核验 Agent 引用的证据、模型版本、可执行动作、实验预算和预先约定的验收结果。
Agent 不能改变物理边界、力阈值、目标定义、真实标签或验收标准来制造通过。
每个决定保存在 `decisions/`，包括当时的上下文、理由和证据。

现阶段训练能力仍是仓库已经实现的联合学习器；Agent 可以安排何时训练和采什么数据，
不能随意编写训练算法、增加运动轴或改变夹持力。独立 B 的数据封存，不用于这一轮调参或补采。

## 状态集合是什么

`learning.target_mode: acceptable_set` 的目标是**可以交给现有力控模块继续抓取的接触状态集合**。
T0 保留作坐标原点和漂移监测参考；偏离 T0 不自动构成位置错误。

- 调用条件：当前接触不符合任务要求，而且观测支持判断需要 a 轴修正。
- 恢复动作：根据触觉估计当前相对位置，向最近的、有真实样本支持的合格接触位置调整。
- 退出条件：新的接触观测被退出模型判为合格，也位于已学习集合中，并通过双侧、稳定、非边缘和新鲜窗口确认。

集合由经过标注的多个合格接触邻域组成，可以包括非零位置，也可以彼此分离。
程序不会把两个合格区域的平均位置或中间未经验证的区域当作合格区域。
已处在合格集合内时可以直接确认退出；恢复后仍须重新观察，不能只靠预测位移宣布成功。
交还控制权时记录目标定义、集合版本、匹配区域和最新接触观测，随后沿用位置确认→力控→主 policy 的链路。

首版复用原有触觉到 a 轴位置的模型来选择目标。新目标锚点来自**实测位置且有明确合格标签的 A 观测**；
开发 B 可以补充状态分类证据，但不会把 B 的修正动作直接当作相对于 T0 的位置标签。
邻域支持和分类验证都不等于主任务成功保证，后续仍需要前瞻 B 和主任务实验。
B 的成功退出还必须与记录中的实际接触窗口一致。每个互不相连的合格区域都需要 B 中的实际达标观测，
不能只验证一个区域就声称整个集合通过；这仍是区域覆盖的初步验证，不代表测试过区域内所有状态。

## 现有 22 次数据怎样复用

新目标 ID 是 `white_bottle_a_acceptable_contact_set_20261110_v2`。
旧数据的 v1 标签定义是理想 T0 区域，不能只改 ID 就当作集合标签。
可以复核原来的观测，创建一个引用同一份原始记录的新标签视图；不需要为了改标签重新移动机器人。
复核时判断“这个接触位置能否交给力控模块”，不能仅判断“有没有碰到触觉胶面”，也不能按 ±mm 自动分类。

离线准备复核材料：

```bash
cd /home/dm/DM_das/bottle_grasp_experiment
bash run_on_5090.sh skill-label-review prepare \
  --session outputs/white_a_current_x5_20261110_fast \
  --config config.white_bottle_a_20261110.set.skill.yaml \
  --out outputs/white_a_20261110_set_review
```

打开复核目录的 `index.html`，核对真实接触窗口并导出标注。页面展示的是已记录的接触描述子几何示意，
不是原始触觉图；信息不足的状态保留“未知”，不凭示意图猜标签。
再用 `skill-label-review apply --review ... --annotations ... --out ...` 创建新视图。

尚需的数据至少涵盖：多个确实合格的位置、靠近合格边界的状态、确实需要恢复的位置，
以及 B 中恢复前/中/后的观测。轻、重瓶均需独立重复。具体补采位置与次数由 Agent 根据复核和训练结果提出。
如果 ±5 mm 都合格，这说明当前范围可能没有位置失败样本；不能把某一档硬标为失败来凑类别，
也不能让 Agent 擅自扩展运动边界。

## 启动方式与离线边界

新版本使用不可变配置快照。已有 campaign 不应强行续跑升级后的代码；新建 campaign，并复用原始记录或复核视图。

```bash
cd /home/dm/DM_das/bottle_grasp_experiment
bash run_on_5090.sh skill-loop init \
  --config config.white_bottle_a_20261110.director.loop.yaml \
  --seed-session outputs/white_a_20261110_set_reviewed \
  --out outputs/white_a_20261110_director_set
bash run_on_5090.sh skill-loop status --out outputs/white_a_20261110_director_set
```

上面 `white_a_20261110_set_reviewed` 是完成复核后创建的视图路径，不是已经存在的训练数据。
`advance` 不连接机器人；加 `--allow-agent` 才调用配置中的外部模型服务发送任务与实验摘要。
没有许可时保留等待状态，不用规则程序伪装 Agent。

真正连续执行仍使用 `skill-loop run --real --allow-agent --out ...`；只有显式确认现场配置后才允许。
默认保留现场放瓶、采集标签和分阶段确认。每个批次结束后流程会继续请求 Agent 决定，
无需再手动切换到训练脚本或 B 命令；遇到复核、暂停、预算终止或硬件故障才停下来。
离线测试使用模拟决策和模拟执行器，不能证明真实 LLM 的实验设计质量或真机成功率。

当前新配置的 `physical_setup_confirmed` 为 `false`。此前的放下悬空和夹紧未达力问题仍需现场核对；
本次代码开发不会把这些未完成的核对改为已通过，也不会启动真机。
